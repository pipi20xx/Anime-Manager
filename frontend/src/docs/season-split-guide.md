# 番剧分季（多季拆分 / 连番号折算）

入口：左侧导航 **工具 → 番剧分季**。页面内四个 Tab：**规则库 / 分组工作台 / 高级 / 黑名单**。

一句话：把「这部番应该怎么分季」写成一条**规则**，识别最后一步用这条规则改写季集号，
让整理落盘（`Season 2/S02E01`）和 Emby 显示都按你想要的季来。

---

## 1. 这个功能解决两类完全不同的问题

| | TMDB 的结构 | 发布侧的样子 | 要做什么 | 要不要写 SYTMDB |
| :--- | :--- | :--- | :--- | :--- |
| **A. 拆分**（合并季） | 只有一季，24 集 | 按「第 1~24 话」或 12+12 发布 | 拆成 S1(12) / S2(12) | **要**（让 Emby 按两季显示） |
| **B. 折算**（连番号） | 已经是 S1 12 集 + S2 12 集 | 仍按「第 1~24 话」连续编 | 把「第 13 话」折成 **S2E1** | **不要**（TMDB 本来就是对的） |

- 两类规则共用同一套引擎（映射表 → 渲染词 → 识别引擎执行），区别只在「源坐标」是谁的编号。
- 「发布侧」指资源发布时用的集号写法：连续编号（第 13 话）、按季编号（S02E01）、或两者混用。

> **判断依据**：A 类看「参照源（TVDB / Bangumi / 规则表）每季集数 **小于** TMDB 实际集数」；
> B 类不需要参照源，答案就在 TMDB 自己的季边界里——「连番号第 i 话」就是「按播出顺序第 i 集」。

## 2. 顶部开关条（全局总闸）

| 控件 | 含义 |
| :--- | :--- |
| **关闭 / 只预览 / 启用** | 关闭＝完全不注入；只预览＝页面能算能看，但识别时不注入；启用＝真正注入识别流程 |
| **整理 / 订阅匹配 / 识别测试** | 作用范围，逐个入口开关；没勾的入口即使「启用」也不生效 |
| **生效规则 N** | 当前内存快照里生效（`active`）且渲染词非空的规则条数 |
| **重载缓存** | 手动强制重载规则快照（保存规则时会自动重载；多容器部署靠 30 秒轮询兜底） |

> 规则注入发生在**识别最后一步**，所以识别结果里的季集号已经是改写后的编号：
> Emby 存在性检查、改名模板 `{season}/{episode}`、整理历史、STRM、通知全都用同一套编号。

## 3. 规则库

每条规则对应**一部番**（主键是 TMDB ID），一条规则里可以有多组（多季）。

### 3.1 卡片上的字段

| 字段 | 说明 |
| :--- | :--- |
| **标题** | 保存时的 TMDB 番名 |
| **TMDB** | TMDB ID |
| **依据** | 这套分组是按什么算出来的：TVDB 集数 / Bangumi 集数 / CureTMDb 规则表 / 播出间隔 / 播出年份 / 季结局标记 / 每 N 集 / 整季（不拆）/ 手动 / **TMDB 季边界** |
| **分组** | 分成几组 · 覆盖多少集 |
| **更新** | 最后一次保存时间 |

### 3.2 三个小标签

| 标签 | 取值 | 含义 |
| :--- | :--- | :--- |
| **状态** | 草稿 / 生效 / 停用 | 只有「生效」会被注入识别；草稿和停用只是存着 |
| **来源** | 手动 / SYTMDB / 自动 / 历史 | 这条规则**是谁写进来的**（写入后不再变）：手动＝工作台保存；SYTMDB＝规则库「导入 SYTMDB」；自动＝识别时自动生成；历史＝升级前的老数据（当时没记来源） |
| **只写渲染词** | （仅连番号折算规则显示） | 这类规则只改识别结果里的季集号，**不会写 SYTMDB 剧集组**，卡片上的「剧集组」按钮是禁用的 |

「来源」和「依据」是两个正交的概念：依据回答「按什么分的季」，来源回答「谁写进来的」。
自动生成和手动保存都可能用 `TVDB 集数` 作依据，所以只看依据分不出来。

### 3.3 工具栏

- **搜索**：番名或 TMDB ID；
- **状态**：全部 / 草稿 / 生效 / 停用；
- **来源**：全部 / 手动 / SYTMDB 导入 / 自动 / 历史未知；
- **类型**：全部类型 / **分季拆分** / **连番号折算**（后者就是上面「只写渲染词」的那批）；
- **刷新**、**导入 SYTMDB**、**新建分季**（跳到分组工作台）。

### 3.4 卡片按钮

| 按钮 | 行为 |
| :--- | :--- |
| **编辑** | 载入到分组工作台（只拉 TMDB 结构 + 已存分组，**不重新拉参照源**）。连番号折算规则的「逐集映射」显示的是 TMDB 原生坐标的恒等表，要看折算结果看「渲染词」页或「高级 → 映射调试器」 |
| **停用 / 启用** | 切换 `active` / `disabled`，不影响已保存的渲染词 |
| **剧集组** | 把 `group_json` 写入 SYTMDB（先探活，404 则创建，再整体覆盖）。连番号折算规则禁用 |
| **删除** | 删掉这条规则，该番恢复按 TMDB 原始季号整理 |

## 4. 分组工作台

流程：输入 TMDB ID → **生成方案** → 右侧挑一个候选 → （可微调）→ **保存并启用**。

### 4.1 候选依据

| 候选 | 说明 |
| :--- | :--- |
| **TVDB 集数 / Bangumi 集数 / CureTMDb 规则表** | 参照源给出的每季集数，**各出一套**并列，可切换对比（不是只取第一个） |
| **播出间隔** | 相邻两集首播日期相差超过阈值（默认 45 天）就切一刀——split cour 的天然特征 |
| **播出年份** | 跨年处切 |
| **季结局标记** | TMDB 的 `episode_type == finale` 处切 |
| **每 12 / 13 集** | 固定集数兜底（高级里可改） |
| **整季（不拆）** | 全部塞进第 1 季 |
| **TMDB 季边界** | 只在「连番号折算」开关开着、且判定无需拆分时出现，默认选中 |

候选按钮上的 chip 会显示「几组 · 每组多少集」，需要拆分的参照源会单独标出来。

### 4.2 三栏

1. **原始季逐集**：TMDB 的集列表（按播出日期摊平），带间隔虚线；
2. **分组编辑器**：起始集 / 结束集 / 季名，可手动加季、调边界、排除个别集；
3. **自动生成**：上面那排候选。

### 4.3 底部输出三页

| 页 | 内容 |
| :--- | :--- |
| **逐集映射** | 原始季/集 → 虚拟季/集，逐条列出，可核对 |
| **渲染词** | 真正注入识别引擎的规则文本（可手动改，保存时按这份入库） |
| **剧集组 JSON** | 推送 SYTMDB 用的剧集组结构 |

右上角：**覆盖 N 集**、**复制渲染词**、**复制剧集组**、**保存并启用**、**写 SYTMDB**（需要先保存过）。

## 5. 连番号折算（B 类）详解

### 5.1 原理

TMDB 的集列表按播出顺序摊平后，第 i 个位置就是「连番号第 i 话」：

```
i=1  → S1E1     i=12 → S1E12
i=13 → S2E1     i=24 → S2E12
```

把这些对应关系交给渲染词编译器，`1..12` 段没有偏移（不生成规则），只有跨季那一段生成一条：

```
# [自动分季] 番名 TMDB:12345 依据=tmdb 2026-11-07
@?{[tmdbid=12345;type=tv;e=13-24]} => {[s=2;e=EP-12]}
```

含义：**当 TMDB ID 是 12345、类型是剧集、集号落在 13~24 时，季号设为 2、集号改为「原集号 − 12」**。
三季番会多一条 `e=25-36 => {[s=3;e=EP-24]}`；单季番一条都不生成（连番号与 TMDB 编号本来就一致）。

### 5.2 开关

**高级 → 默认参数 → 无需分季时附带「连番号折算」**（默认关）。

打开后：

- 分季判定为「无需拆分」时，**多给一个「TMDB 季边界」候选**并默认选中；
- 不管选哪个候选，只要分组是恒等映射（没改动季集号），保存时都会把折算那一段追加进渲染词；
- 需要拆分的番（A 类）不会追加——两个方向不会打架。

> 和「使用 includes 年份渲染词」是同一层的开关：**只影响「生成什么渲染词」，关掉就和以前完全一致**。
> 它不会追溯修改已经保存的规则——那些规则的渲染词是保存时编译好存进库的，
> 想让它带上折算段，在工作台载入该番后重新保存一次即可。

### 5.3 为什么不写 SYTMDB

折算规则的分组、映射表、剧集组都是 **TMDB 原生坐标的恒等映射**（第 1 季还是第 1 季），
只有渲染词里多了一段。所以：

- 剧集组推上去等于 TMDB 自己，没有任何意义；
- 自动生成的路径根本不调用推送接口；
- 即使手动点「剧集组」，按钮是禁用的；直接调接口也会被后端拒绝。

### 5.4 边界情况

| 情况 | 行为 |
| :--- | :--- |
| 文件名带季标 `S2E01` | 不落在 13~24，保持原值（正确） |
| 文件名带季标又问连号 `S2E13` | 命中，折成 S2E1（救回来） |
| 合集文件 `13-24` | 起止集号一起改，落成 `S2E1-12` |
| 跨季合集 `11-14` | 折成 S2E1-4（跨季被打包，落盘只在一个季里） |
| S0 特别篇 | 不参与连番号序列（不占序号） |
| 两季都从 01 数（`S2 - 01`） | 不命中折算区间，保持原值（正确） |
| TMDB 少登记了几集 | 可能把 `S1E13` 误折成 `S2E1` —— 卡片可见（依据=TMDB 季边界、来源=自动），停用或删除即可 |

## 6. 自动流程与黑名单

「自动生成规则」开关打开、模式为「启用」、且当前入口在作用范围内时，识别到**没有规则的番**会走这条链路（每一步按顺序判定，命中就结束）：

```
没有规则的番
     │
     ├─ 黑名单里已有？            → 什么都不做
     ├─ TMDB 单季且集数 < 15？    → 直接进黑名单（不拉参照源，省一次网络往返）
     │
     └─ 拉 TMDB 结构 + 参照源
          ├─ 需要拆分（参照集数 < TMDB 集数） → 生成「分季拆分」规则（生效，当场注入本次识别）
          │
          └─ 无需拆分
               ├─ 折算开关开 + TMDB ≥ 2 季 → 生成「连番号折算」规则（生效，当场注入，不写 SYTMDB）
               └─ 否则 → 加入黑名单
```

> **快速拉黑的阈值**：**TMDB 只有一季、且集数 &lt; 15** → 直接进黑名单。
> 这种番既拆不出两季，也没有可折算的跨季边界，怎么处理都一样。
> 常量：`backend/season_split/constants.py` 的 `SINGLE_SEASON_BLACKLIST_MAX = 15`（正好 15 集不拉黑）。
> 集数未知或没有季表时不走快速判定，退回上面的正常流程。

### 6.1 黑名单意味着什么

- 黑名单里的番**永远不会套用分季规则**（识别注入时直接跳过）；
- 也**不会**再自动生成规则（自动流程第一步就跳过它）；
- 黑名单按 TMDB ID 记录，和规则互不影响——已有规则的番不会被自动拉黑。

### 6.2 黑名单页

- 列表显示名称 / 年份 / 海报（读本地永久缓存与数据中心元数据，不联网；查不到显示「未收录」）；
- 顶部输入 TMDB ID 可手动添加；
- 卡片「移出黑名单」后，**下次识别会重新判定一次**：如果结论仍是「不需要处理」，会再次被自动加入；
- 想让某部番彻底不参与分季，就把它留在黑名单里。

## 7. 与 SYTMDB / Emby 的关系

| 场景 | 要不要写剧集组 | 原因 |
| :--- | :--- | :--- |
| A 类：TMDB 把两季并成一季 | **要** | Emby 只认 TMDB 的季结构，得靠剧集组告诉它「第 13 集属于第 2 季」 |
| B 类：TMDB 本来就是两季 | **不要** | 文件整理成 `S02E01` 后，Emby 靠 TMDB 原生季结构就能对上 |
| 只改识别、不改 Emby | 不要 | 例如你只用本项目的整理功能，Emby 那边不看 |

写剧集组是**整番覆盖**（先探活，不存在就创建，再整体 PUT），会立即改变 Emby 的季显示。

## 8. 执行顺序与优先级

1. 你自己的「自定义渲染词」先执行；
2. 番剧分季规则**最后**执行（日志里带 `[分季]` 标记，命中会打印 `🎯 [Render][分季] 命中专家规则`）；
3. 两者冲突时，以分季结果为准。要否决某番，用**黑名单**或直接改分组，不要靠再写一条规则盖回去。

命中后识别日志会出现：

```
🔀 季集号已变更: S1E13 → S2E1
```

## 9. 高级设置逐项说明

### 9.1 默认参数

| 选项 | 说明 |
| :--- | :--- |
| **参照优先级** | 只决定「生成方案」默认选中哪个参照源，不再决定「只取哪一个」 |
| **启用 CureTMDb 规则表** | 需要填地址；命中即用，不依赖后面的国家/季数门槛 |
| **强制参照** | 跳过「日本动画 + 有效季数 1~2」的门槛，对所有番都尝试 TVDB / Bangumi |
| **使用 includes 年份渲染词** | 按虚拟季首播年份生成 `includes=2016` 这类条件规则 |
| **无需分季时附带「连番号折算」** | 本页第 5 节；关掉即恢复旧行为 |
| **自动生成规则** | 识别到无规则的番时自动建规则（需要模式=启用 + 作用范围勾选） |
| **自动写入 SYTMDB 剧集组** | 自动生成「拆分」规则后顺带推送剧集组；折算规则永不推送 |
| **规则表地址** | CureTMDb 规则表 URL，留空＝不使用 |
| **间隔切分阈值** | 「播出间隔」依据的切分天数，默认 45 |
| **TVDB Key** | 留空用官方共用 Key |

### 9.2 参照门槛

只影响自动拉取 TVDB / Bangumi（开了「强制参照」就全跳过）：
动画类型（TMDB genre id）、出品国家（ISO 码）、有效季数上下限、固定集数兜底、间隔虚线阈值。

### 9.3 映射调试器

输入 **TMDB ID + 季 + 集**（可选文件名，用于验证 `includes` 年份规则）→ 回放该番已保存的规则：

```
S1E13 → S2E1（状态 active，依据 TMDB 季边界）
```

它直接读库里的渲染词文本，所以看到的就是识别时真正会执行的结果。排查「为什么这集没变」优先用它。

## 10. 排查清单

| 现象 | 先查什么 |
| :--- | :--- |
| 第 13 集没变成 S2E1 | ① 顶部是不是「启用」；② 规则状态是不是「生效」；③ 这条规则保存时折算开关是否已打开（已存的规则不会自动补）；④ 该番是否在黑名单；⑤ 用调试器回放 `1/13` 看规则到底有没有命中 |
| 卡片显示「只写渲染词」但没有效果 | 这是折算规则，只在 13~24 这类跨季集号上命中；单季番不会生成 |
| 番莫名进了黑名单 | 两种自动来源：单季且集数 &lt; 15，或「无需拆分且生成不出折算规则」 |
| 移出黑名单后又回去了 | 说明判定结论仍是「不需要处理」；要强制处理就手动在工作台建一条规则保存 |
| 规则建了但整理没变 | 作用范围没勾「整理」，或模式是「只预览」 |
| Emby 显示没变 | A 类规则需要点「剧集组」推送；B 类不需要也不该推 |
| 保存报「分组为空」 | 分组没覆盖任何 TMDB 集（起止集写错，或整季被排除） |
| 改了 TMDB 季结构 | 重新「生成方案」并保存，会按最新结构重算映射与渲染词 |

## 11. 规则文本长什么样（需要手改时看）

分季规则的渲染词就是普通的专家条件规则，一行一条：

```
# [自动分季] 番名 TMDB:12345 依据=tvdb 2026-11-07
@?{[tmdbid=12345;type=tv;e=13-24]} => {[s=2;e=EP-12]}
@?{[tmdbid=12345;type=tv;includes=2025]} => {[s=2]}
```

- `tmdbid` / `type` / `e`（可写区间 `13-24`）/ `s` / `includes` 是条件；
- `{[s=..;e=..]}` 是动作，`e` 支持公式（变量 `EP`，即当前集号）；
- 注释行（`#` 开头）会被忽略，只用于标注来源；
- 在工作台「渲染词」页手改后保存，以你改的文本入库（会提示「已手动修改」）；
  下次点「从分组重新生成」会按分组 + 当前开关重新编译。

## 12. 常见问题

**Q：能不能只给某一部番开连番号折算？**
开关是全局的（和 includes 一样）。单番层面的做法有两种：
① 在工作台「渲染词」页把那几行连番号规则删掉再保存（保存时以你改的文本入库）；
② 把这部番加进黑名单（它就不再参与分季）。

**Q：打开开关后，之前保存的规则会变吗？**
不会。渲染词是保存那一刻编译好写进库的；开关只影响之后新生成/重新保存的规则。

**Q：黑名单和「停用规则」有什么区别？**
停用是「这条规则先不生效，但规则还在」；黑名单是「这部番不参与分季，连自动生成都跳过」。

**Q：为什么我不用它也能整理？**
不用分季规则时，季集号完全按 TMDB 原始结构走。只有「发布侧编号和 TMDB 不一致」时才需要它。

**Q：会不会改到 TMDB 或 SYTMDB 的数据？**
识别/整理只改本地改写结果；只有你点「剧集组」（或打开自动写入）才会写 SYTMDB；
折算规则永远不会写。

**Q：规则存在哪里？**
数据库表 `public.season_split_rules`（每部番一条），识别热路径只读内存快照。
