## 字体管家 (assfonts) 使用说明

把 ASS 字幕用到的字体**精简 + 内嵌**进字幕文件，成品脱离字体库也能正常显示 —— 手机、电视、NAS 播放器都不会再因为缺字体而乱码或变方块。

内核是开源项目 [assfonts](https://github.com/wyzdwdz/assfonts)，本项目把它做成了网页版，并**完整暴露了内核的全部命令行能力**。

---

### 一、快速上手（三步）

> **💡 前置条件：** 先准备一个**字体库文件夹**（里面放 `.ttf/.otf/.ttc` 字体文件），在「设置」里选中它并重建索引。

1. **选字体库** —— 首次打开页面会看到引导卡片，点「选择字体库文件夹」挑一个目录（建议放在媒体池，例如 `/202nvme/fonts`），系统会自动建立字体索引。
2. **拖入字幕** —— 把 `.ass` / `.ssa` 字幕（**也可以直接拖整个文件夹**，会自动递归找出里面的字幕）拖到页面中间的虚线框里，松手即上传。上传时会**立刻预检缺字体**，不用等处理完就知道缺什么。
3. **选模式并执行** —— 在工具栏选好「处理模式」，点单行「执行」或顶部「全部子集化」，成功后点「下载」。

---

### 二、五种处理模式

工具栏的「处理模式」下拉决定本次如何加工字幕：

| 模式 | assfonts 参数 | 产出 | 适用场景 |
| --- | --- | --- | --- |
| **子集化 + 内嵌**（默认） | 无 | `原名.assfonts.ass` | 常规用法，一步到位 |
| **仅子集化字体** | `-s` | **字体包 zip**（`原名_subsetted/`） | 只要裁剪后的字体文件，字幕自己另行处理 |
| **仅内嵌字体** | `-e` | `原名.assfonts.ass` | 字体**已裁剪过**，只需原样嵌入（成品体积大） |
| **清除已内嵌字体** | `-e -s` | `原名.cleaned.ass` | 把已内嵌字体的字幕还原成干净字幕（输入没有内嵌时状态为「已跳过」） |
| **合并子集化** | `-c` + `-e`（两阶段） | 每个 `原名.assfonts.ass` | **多个字幕共享同一份子集字体**，避免每个字幕各带一份重复字体 |

> **💡 关于「合并子集化」：** 内核的 `-c` 参数**本身只产出字体夹、不产出字幕**，所以本功能自动跑两阶段：先把所有待处理字幕的字体合并子集化成一份，再逐个嵌入。建议一次批量处理同一部剧的多集字幕。

### 三、处理方式（参数逐项说明）

| 设置项 | 参数 | 说明 |
| --- | --- | --- |
| 字体库目录 | `-f`（建索引） | 字体来源，**必填**；支持配置**多个**字体库目录，索引时会叠加 |
| 额外字体目录 | `-f`（处理时） | 本次处理额外补充的字体来源；「仅内嵌」模式常用它指向已裁剪的字体夹 |
| 输出目录 | `-o` | 所有成品（含 `_subsetted`）统一放到该目录；留空则放在任务工作目录。**不存在的目录会自动创建**（内核自己不会建，会直接报错） |
| 重命名字体 | `-r` | 把内嵌字体重命名为随机名，避免与播放器所在系统的同名字体冲突 |
| HDR 亮度 | `-l` | 压暗字幕颜色，避免 HDR 片源下纯白字幕刺眼。开关 + 数值（默认 203）。开启后成品名会带 `.hdr`（内核命名规则），下载时仍给你规范文件名 |
| 内核内部线程数 | `-m` | 0 = 内核默认（通常 CPU 核数 + 1）；字幕很多时调大可加速 |
| 内核日志级别 | `-v` | 0~3，默认 3。**低于 2 时内核不再输出缺字体提示**（详见下方「缺字体判定」） |
| 保留 `_subsetted` 字体文件夹 | — | 是否保留裁剪后的字体文件，一般不需要可关闭 |
| 成功后删除源字幕副本 | — | ⚠️ 删除后该任务无法再次重试 |

### 四、字体从哪来（字体库 / 上传 / 临时字体）

#### 1. 多个字体库目录

字体来源可以配**多个**目录（设置 → 字体来源）：

| 配置项 | 作用 |
| --- | --- |
| **字体库目录** | 主字体库，必填 |
| **额外字体库目录** | 可加任意多个；建索引时与主库**叠加**（内核会收到多个 `-f`） |

点「重建索引」会把所有目录一起扫描进同一份索引。字体库面板的字体数、缺字体判定也都按这几个目录的范围过滤。

> **💡 换目录会自动让旧索引失效**，需要重新点一次「重建索引」，避免用错口径判断字体齐不齐。

#### 2. 永久上传字体（入库）

字体库面板 →「**上传字体到字体库**」：选中的 `.ttf/.otf/.ttc/.otc/.woff/.woff2` 会**写入主字体库目录**，并按设置**自动重建索引**，立即可用于处理。

* 同名且内容完全相同 → 自动跳过，不重复占空间
* 同名但内容不同 → 另存为 `原名_1.ttf`，**绝不覆盖**你已有的字体

#### 3. 临时上传字体（不入库）

「**临时字体**」区块 → 上传（或直接把字体文件拖到该区块）：字体存进独立的临时字体池，**不会写进字体库**。

* 处理时会作为**补充字体源**自动参与（内核 `-f`），与索引叠加生效
* 缺字体预检也会立刻把这些字体算作"已具备" —— 传完就能看到任务行不再报缺
* 一个典型用法：某集缺一个冷门字体，传上去直接跑完下载，然后「清空全部」即可，字体库保持干净

> **⚠️ 为什么入库要按钮、临时可以拖拽？** 入库是**永久写盘**动作，刻意只留按钮避免误操作；临时字体随用随清，拖拽更顺手。

### 五、交付物与下载

一条任务可能有多种交付物，下载按钮按需展开：

| 交付物 | 出现时机 | 说明 |
| --- | --- | --- |
| **成品字幕** | 模式为「子集化+内嵌」/「仅内嵌」/「合并子集化」 | `原名.assfonts.ass`，已内嵌字体，直接替换原字幕即可 |
| **清理版字幕** | 模式为「清除已内嵌字体」；或对已内嵌字幕做其它处理时附带生成 | `原名.cleaned.ass`，不含内嵌字体的干净字幕 |
| **子集字体包** | 模式为「仅子集化字体」（这就是主交付物）；或其它模式保留了 `_subsetted` 时可选下载 | zip，内含裁剪后的 `.ttf` |

> **💡 输出目录（`-o`）：** 配了输出目录时，所有成品都集中放到那里，取用方便。
> 如果同一批里有**同名**字幕（例如两个文件夹下都叫 `01.ass`），系统会把后一个自动隔离到
> `<输出目录>/<任务ID>/` 下，**不会互相覆盖**。

### 六、缺字体判定（为什么值得单独说）

assfonts 有个反直觉的行为：**无论成功还是失败，退出码永远是 0**；而且把日志级别 `-v` 调到 2 以下时，连 `Missing the font` 警告都会被一起吞掉。

所以本项目**不看退出码**，而是：

1. 先解析内核日志里的 `Missing the font: "xxx" (400,0)`；
2. 日志被静默（`-v < 2`）时，改用**索引里的字体名集合与字幕引用字体自行比对**，照样能列出缺哪几个字体。

任务行上会直接显示缺失字体清单，补齐字体 → 重建索引 → 点「重试」即可。

### 七、内核更新

项目内置 **assfonts v0.7.3**。上游发布新版本后：

1. 点状态条右侧的「检查更新」；
2. 若提示有新版本，点「立即更新」——下载约 20 MB 官方构建包，校验 ELF 架构与可执行性后原子替换；
3. 更新后的内核存放在 `data/bin/assfonts`（数据卷内），**重建镜像不会丢失**。

> **💡 关于限流：** GitHub 对未登录 API 请求按 IP 限流（60 次/小时）。本项目在 API 被限流时会自动改用 Release 页面跳转解析版本号并推算资产地址，同时用 HEAD 探测包大小 —— 所以限流不影响使用。

### 八、常见问题

**Q：字幕显示缺字体，但字体明明放进去了？**
① 字体库目录变更后需要重建索引；② 注意字体名要对得上 —— ASS 里写的是字体内部名称（如 `霞鹜文楷` / `LXGW WenKai`），**文件名不一定等于字体名**。

**Q：`.otf` / `.ttc` 内嵌后播放器不显示？**
ASS 规范只允许内嵌 **TrueType (`.ttf`)** 字体，assfonts 会强行内嵌非 TTF 字体，部分播放器可能不加载。建议字体库优先使用 `.ttf`。

**Q：为什么「仅内嵌」出来的文件特别大？**
因为它不做裁剪，把完整字体原样塞进字幕（实测 24.7 MB 字体 → 成品约 31 MB）。想要小体积请用默认的「子集化 + 内嵌」。

**Q：「合并子集化」和普通「子集化 + 内嵌」有什么区别？**
普通模式每个字幕各带一份自己的子集字体；合并模式让一批字幕**共用一份**子集字体，整季字幕的总体积更小。

**Q：字幕缺一个冷门字体，必须把它放进字体库吗？**
不必。用「临时字体」上传即可 —— 它只在处理时作为补充字体源，不入库，跑完一键清空。

**Q：点了「清理已完成」，为什么列表里还有任务？**
「清理已完成」只清 `success`（成功）与 `skipped`（已跳过）；**待处理 / 缺字体 / 失败**都属于"还没了结"，会保留下来方便你补齐字体后重试。想一次清干净，点该按钮右侧的下拉箭头 →「清空全部」。正在处理中的任务永远不会被清理。

**Q：字体库目录可以放多个吗？**
可以。设置 → 字体来源里加「额外字体库目录」，建索引时会一起扫描并叠加。

**Q：成品能直接覆盖原字幕吗？**
可以，成品与原名只差后缀，下载后自行替换即可。字体管家**不会**自动改动你的媒体库字幕文件；只有整理任务里主动开启了「随行字幕子集化」，才会在整理时把内嵌成品写进目标目录（详见第九节）。

### 九、随行字幕子集化（整理任务联动）

整理任务的高级选项里有一个「随行字幕子集化」开关。开启后，整理每个视频时会顺带处理同目录下随行的 `.ass` / `.ssa` 字幕：

- **成功**：字幕做「子集化 + 内嵌」，成品随视频一起进目标目录，文件名带 `.assfonts` 标记
  （如 `Show - S01E01.zh.assfonts.ass`）。后缀仍是 `.ass`，播放器照常识别，标记只是方便你一眼看出哪些字幕内嵌过字体；
- **缺字体 / 失败 / 已内嵌 / 非 ASS 字幕**：不做处理，**原字幕照常搬进目标目录**；
- 两种情况下源目录都不会留下孤儿字幕：move 类动作下成品写入成功后才会删掉源原件，
  目标已存在被跳过或写入失败时保留原件，不会丢文件。

前提：字体管家已配置字体库并建好索引。没配好时整个步骤会自动跳过，只在任务日志里留一条 WARN，**不影响整理本身**。

几个细节：

- 一次处理多个字幕时（比如简繁双语），会自动走「合并子集化」，共享一份子集字体，避免每个字幕各带一份；
- 缺字形（`Missing codepoints`）只警告，成品照常产出，不影响交付；
- 缺字体时可以先补齐字体（字体库或临时字体池），再到「整理历史」里对那条记录点「重试」，会重新做一次子集化；
- 云盘源（CD2 源）的字幕也支持：会先下载到临时目录做子集化，再上传到源目录下的 `.assfonts_tmp/`，由整理流程随视频一起搬走；搬完自动删掉云端原件和临时目录。下载或上传失败时按原字幕搬运；
- 中间产物写在 `data/fonts/organize_tmp/<任务ID>/` 下，处理完即删，不会污染媒体目录。

### 十、处理历史（整理任务联动）

「处理历史」Tab 记录每一次**随行字幕子集化**的结果 —— 成功也记、缺字体也记，不会静默。

每条记录包含：

- 原字幕文件名 + **交付路径**（点一下即可复制）
- 结果：已内嵌 / 缺字体 / 失败 / 已跳过，缺字体时会列出具体字体名
- 重试次数、处理时间、文件大小

**为什么值得单独做一页**：记录里存的是交付路径。等字体补齐之后，点「重新子集化」就会按这条路径把文件找回来重做一次，
成功时**就地替换**（生成 `xxx.assfonts.ass`，旧的未内嵌文件删掉），失败则把新的缺字体清单写回记录。
即使字幕被改过名（比如手动去掉了 `.assfonts` 标记），也会在同目录按主干名找回来，不依赖当初的完整文件名。

工具条上的两个批量操作：

- **批量重试缺字体**：把所有「缺字体」的记录一次重跑（一次最多 50 条），补完字体后点一下就行；
- **清理**：默认只清「已内嵌 / 已跳过」，缺字体与失败的会保留，方便你补完字体再重试。

> 记录只反映「整理时」的结果。之后你手动改过字幕内容，这里的状态不会跟着变，需要时直接重试一次即可。

**云端（CD2）目标也能重试**：记录里会标一个 `CD2` 标记。重试时后端会用 CD2 接口把字幕**下载到临时目录 → 本地子集化 → 再上传回去**，
成功后旧的未内嵌字幕会被删掉，只留 `xxx.assfonts.ass`。云端文件被改过名同样能在原目录按主干找回来。
（云端路径没法用本地 `stat` 判断存在性，所以列表里不会显示「文件已不在」，以重试时的报错为准。）
