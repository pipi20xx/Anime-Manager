# 设置说明

系统设置入口为侧边栏的 **[系统设置]** 页面，包含六个标签页：

| 标签页 | 内容 |
|--------|------|
| **基础配置** | TMDB / Bangumi / SYTMDB / 识别偏好 / Jackett / Emby / Telegram 通知 / 代理 / 磁盘空间回收规则 |
| **下载器管理** | 下载客户端（qBittorrent / CloudDrive2）的添加、编辑、删除、测试 |
| **识别与订阅规则** | 自定义识别词 / 制作组 / 渲染词 / 特权规则（本地 + 远程订阅） |
| **账号与安全** | 密码修改、2FA、会话管理 |
| **服务状态** | 系统服务、文件监控任务、运行时统计、规则统计 |
| **掉盘与失效检测** | 硬盘掉线 / CD2 可达性 / Cookie 失效的定时巡检配置 |

> 定时任务相关设置（RSS 刷新、规则同步、订阅补全、死种清理、磁盘空间回收的启用开关与巡检周期等）已迁移至 **[任务计划]** 页统一管理。AI 助手相关设置在独立的 **[AI 实验室]** 页面；外观与壁纸在顶栏的主题菜单中配置（见文末）。

### 识别偏好设置

### 网络代理设置

| 配置项 | 说明 |
|--------|------|
| HTTP 代理 | 支持 `http://ip:port` 或 `http://user:pass@ip:port` |
| 代理服务 | 勾选走代理的服务：TMDB / Bangumi / 远程规则 / Docker Hub / Jackett / Telegram / RSS 订阅 |

### 磁盘空间回收规则

监控 QB 种子占用体积，超过阈值后从最老的种子开始删除。回收功能的**启用开关与巡检周期**请在「任务计划」页的「磁盘空间自动回收」卡片中管理，此处仅配置回收规则。

每条规则包含：

| 配置项 | 说明 |
|--------|------|
| 指定下载器 | 不选则对所有 QB 生效 |
| 监控路径 | 如 `/downloads` |
| 体积上限 (GB) | 超过上限即触发回收 |
| 最少做种数保护 (0=不保护) | 做种数低于该值的种子不删除 |
| 保护标签 (逗号分隔) | 带有这些标签的种子不删除，如 `keep,important` |

规则支持「预览」（查看各组占用与计划删除清单）和「执行」（立即回收）。

## 二、下载器管理

在 **[系统设置] → [下载器管理]** 中添加、编辑、删除下载客户端，保存前可「测试连接」。

支持的客户端类型：**qBittorrent** 与 **CloudDrive2**（CD2 客户端仅可添加一个）。

通用配置项：

| 配置项 | 说明 |
|--------|------|
| 类型 | qBittorrent / CloudDrive2 |
| 名称 | 给它起个名字 |
| 地址 (URL) | 如 `http://192.168.1.x:8080` |
| 用户名 / 密码 | 下载器登录凭据 |
| API Token / API Key (选填) | QB 5.2.0+ 可用（填写后无需账号密码）；CD2 填写后直接使用 API Token 认证 |
| 默认下载路径 (选填) | 留空则使用下载器全局设置 |
| 设为默认客户端 | 开启后作为新增下载任务的默认下载器 |

### CD2 (CloudDrive2) 设置教程

#### 1. CD2 下载器配置（gRPC 连接）

番剧管家通过 CloudDrive2 的 **gRPC 接口** 与 CD2 深度集成。在 **[系统设置] → [下载器管理]** 中添加类型为 **CloudDrive2** 的下载器：

| 配置项 | 说明 |
|--------|------|
| 地址 (URL) | CD2 的访问地址，如 `http://192.168.50.12:19798` |
| 用户名 / 密码 | CD2 登录凭据 |
| API Token (选填) | 填写后直接使用 API Token 认证，无需用户名密码 |
| 默认下载路径 (选填) | CD2 云盘路径（如 `/115open/downloads`），作为订阅/下载的默认落点 |
| CD2 本地挂载点 (选填) | 本地挂载视图路径（如 `/medata/CloudDrive`），用于云路径 ↔ 本地路径自动换算；gRPC 免挂载场景选填，本地扫描/Webhook 匹配场景建议填写 |
| 后台传输监控 | 开启后轮询 CD2 传输任务状态，完成后自动触发 STRM 生成与通知 |
| 监控间隔 (秒) | 传输监控的轮询周期 |

![CD2下载器设置](./cd2-downloader-settings.png)

#### 2. 免挂载 gRPC 能力

配置好 CD2 下载器后，以下功能全部通过 gRPC 接口完成，**无需将网盘挂载到本地**：

*   **STRM 免挂载同步**：STRM 任务「同步模式」选择 **CD2 云盘 (gRPC)**，源目录直接填云路径（详见「使用指南 → 虚拟库 (STRM)」）
*   **免挂载云整理**：整理任务源/目标目录类型选择「CD2 云盘」：云 → 云走服务器端移动/复制，云 → 本地走 CD2 下载接口直接下载，本地 → 云走 Remote Upload 上传
*   **云端单文件识别**：在 CD2 管理中心「文件浏览」中可直接对云端文件识别并整理式重命名
*   **云端哈希计算**：通过 CD2 API 流式取流计算 SHA1/ED2K，无需落盘
*   **离线下载管理**：磁力/种子推送到网盘离线下载，任务列表/配额/删除管理
*   **CD2 管理中心**：[CD2] 页面的文件浏览、传输监控、深度删除、协议管理（gRPC proto 自动下载编译）

#### 3. CD2 容器挂载配置（按需）

以下场景仍需要将 CD2 挂载到本地，并正确配置容器挂载传播：

*   STRM / 整理任务使用「本地文件扫描」模式读取挂载目录中的文件
*   Emby / Jellyfin 等播放器需要直接读取挂载路径中的媒体文件播放
*   Webhook 联动「本地文件扫描」模式的 STRM 任务（需要按挂载点换算路径）

##### CloudDrive2 容器挂载配置

在使用CloudDrive2（CD2）时，需要正确配置容器挂载，以确保其他容器能够访问CD2挂载的网盘文件。

##### Docker Compose 配置

在CD2的docker-compose.yml中，需要添加两条挂载规则：

```yaml
volumes:
  # 第一条：给CD2的compose使用（shared模式）
  - /vol1/1000/NVME/docker2/clouddrive2-19798/medata:/medata:shared

  # 第二条：其他需要挂载CD2的容器使用（rslave模式）
  - /vol1/1000/NVME/docker2/clouddrive2-19798/medata:/medata:rslave
```

##### 挂载模式说明

- **shared**：CD2容器自身使用，允许挂载传播
- **rslave**：其他容器使用，只接收挂载传播

## 三、识别与订阅规则

**[系统设置] → [识别与订阅规则]** 包含四组规则卡片，每组均分左右两栏：

*   **本地规则**（可编辑）：每行一条，即时生效
*   **远程订阅**（仅同步）：填写规则 txt 的 URL，每行一个，通过右上角「同步远程规则」按钮拉取

| 规则卡片 | 格式示例 |
|---------|---------|
| 自定义识别词 | `10月新番`（屏蔽词）；或 `藤本树 17-26 => 藤本树 17_26`（替换） |
| 自定义制作组 | `SweetSub`、`Mikanani`（每行一个制作组名） |
| 自定义渲染词 | `剧场版 => {[type=movie]}`、`S2 => {[s=2]}` |
| 自定义特权规则 | `正则表达式 => {[字段=值;字段=值]}`，如 `^\[([^\]]+)\]\s+(.+?)\s+-\s+(\d{1,4}) => {[group=\1;title=\2;e=\3]}`；加 `ai=1` 字段可使命中文件直接交给 AI 识别（如 `\[晚街與燈\] => {[group=晚街與燈;ai=1]}`） |

各规则类型的详细语法说明见「识别规则」「渲染词」「特权规则」专篇文档。

## 四、账号与安全

### 凭据管理

填写当前密码、新密码、确认新密码后点击「立即更新密码」。

### 多重身份验证 (2FA)

TOTP 动态验证码开关。开启后展示二维码与密钥，使用验证器应用扫码并输入 6 位验证码确认；每次登录时系统都会要求提供动态码。未开启时页面会提示高风险警告。

### 会话管理

*   **JWT 令牌永不过期**：开启后登录令牌将不会自动过期（10 年），关闭后为 24 小时自动过期。永不过期会降低安全性，建议仅在可信环境中使用
*   **会话列表**：展示每个会话的浏览器 / 系统、IP、登录时间与过期时间，当前会话有标记；可单独「踢出」某个会话，或「踢出所有其他设备」
*   **退出登录**：页面底部显示当前登录用户名与最近登录时间，可退出登录

## 五、服务状态

只读监控页，右上角可开关「自动刷新」（约 3 秒轮询一次）：

*   **系统服务**：各内置服务的运行状态、执行间隔、下次执行 / 上次同步时间与描述
*   **文件监控任务**：整理 / STRM 监控的运行状态、模式（含「接受联动」「Emby检查」「哈希计算」标记）、源目录与目标；运行中的任务显示待处理队列数量，点击「查看队列」可实时查看排队文件（首条标记为正在处理）
*   **运行时统计**：文件观察器 / 工作线程 / 任务队列数量
*   **规则统计**：自定义识别词、自定义制作组（本地 / 远程 / 内置）、自定义渲染词、特权规则的条数统计

## 六、掉盘与失效检测

通过定时检测指定文件是否存在，用于监测本地硬盘是否掉线、CD2 云端是否可访问，或下载源的 Cookie 是否失效。

### 全局设置

| 配置项 | 说明 |
|--------|------|
| 自动巡检 | 定时检测硬盘掉线和 Cookie 失效 |
| 巡检频率 (分) | 巡检间隔（分钟） |
| 立即检测全部 | 手动触发所有配置的检测 |

### 检测配置

| 配置项 | 说明 |
|--------|------|
| 配置名称 | 如「阿里云盘掉盘检测」 |
| 文件路径类型 | **本地路径**（文件存在 + IO 读取验证）或 **CD2 云盘**（gRPC 云端文件存在性检查，路径如 `/115open/check.txt`） |
| 文件路径 | 待检测的文件，可从文件浏览器选择 |
| 远程 URL | 文件的直链 URL（包含 Cookie 或 Token） |
| 启用检测 | 关闭后不参与巡检 |

**判定逻辑**：仅填写文件路径 → 只检测文件是否存在；同时填写远程 URL → 文件存在后再请求 URL，HTTP 非 200/206 则判定 Cookie 失效。状态标签显示为 正常 / 异常 / 未检测。

## 七、AI 实验室（独立页面）

**[AI 实验室]** 页面包含六个标签页：**AI 对话**、**工具列表**、**技能管理**、**助手配置**、**AI 介入测试**、**Telegram Bot**。

### 助手配置

**AI 模型配置：**

| 配置项 | 说明 |
|--------|------|
| 模型提供商 | Ollama (本地) 或 OpenAI / 兼容接口 |
| API 地址 | Ollama 默认 `http://localhost:11434`，OpenAI 兼容接口填完整 v1 地址 |
| API Key | 仅 OpenAI 兼容接口需要 |
| 模型名称 | 如 `qwen2.5:7b` 或 `gpt-4o`，可点击「拉取列表」从 API 读取可用模型直接选 |

**推理参数：**

| 配置项 | 说明 |
|--------|------|
| 温度 | 0 - 2，控制输出随机性 |
| 思考深度 | 跟随服务端默认（auto）/ 关闭（off）/ 最低（minimal）/ 低 / 中 / 高 / 最高（max）/ 极高（xhigh）；「探测能力」会确认该模型用哪种参数能关掉思考并缓存复用 |
| 最大输出 Token 数 (K) | 发给模型的单轮输出上限，单位千（64 → 64000），不是会话记忆上限 |
| 历史条数上限 / 历史 Token 预算 | 会话记忆的双上限：超出先把最旧消息压成摘要，再超就硬截断（Token 预算填 0 表示只按条数限制） |
| 最大迭代次数 | 单次对话允许的工具调用轮数上限 |
| 允许 AI 操作（工具调用） | 开启后 AI 可调用搜索、订阅、整理等工具执行实际操作；关闭仅能聊天问答。Telegram Bot 未单独设置时也使用该全局默认值 |
| 动态工具选择 | 开启：按消息内容自动挑选相关工具（省 token）；关闭：把全部工具提供给模型（更稳但更耗 token） |
| AI 智能介入 | **全局兜底**：常规识别全部失败后让 AI 猜测标题并重新搜索。此外特权规则命中 `ai=1` 时会**优先**触发 AI 介入（无需打开此开关，集数也一并交由 AI 裁决），详见「特权规则」专篇 |
| AI 识别结果不写入智能记忆 | **开启（默认）**：AI 介入（含特权规则 `ai=1` 触发）识别成功的文件不记入智能记忆，后续集数会继续走 AI 裁决；关闭：AI 识别成功后照常写入记忆，后续集数走记忆加速 + 常规解析（怪命名作品可能集数出错） |

提示：智能记忆命中或已锁定 TMDB ID 的文件会直接跳过 AI 介入（包括特权规则触发的介入）——智能记忆只存"作品 ↔ ID"的对应关系，命中后集数走常规解析。对命名怪异（如 `[4th - 19]` 这类会被误解析）的作品，请保持「AI 识别结果不写入智能记忆」开启（默认开启），让每一集都由 AI 裁决。

### AI 介入测试

输入文件名，让 AI 推断真实标题。模拟识别失败后 AI 介入猜测标题的行为，仅测试 AI 推断能力，不涉及 TMDB/Bangumi 搜索。与全局兜底、特权规则 `ai=1` 调用的是同一个推断能力。

### Telegram Bot

| 配置项 | 说明 |
|--------|------|
| 启用 Bot 对话 | 通过 Telegram 与智能助手对话，远程控制番剧管理 |
| 允许的 Chat ID | 多个用逗号分隔，留空则不限制 |

提示：配置保存后需**重启服务**才能生效；需要先在「系统设置 → 基础配置」中配置 Bot Token。

### 壁纸管理

| 设置项 | 说明 |
